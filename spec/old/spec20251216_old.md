# tfplan-viewer 現行仕様 (2025-12-16)

## システム概要

3段階パイプライン処理でTerraform plan.jsonをHTMLテーブルに変換する。

```
plan.json + schema.json
    ↓
[1] data_extraction.py
    ↓
extracted.json (OriginValue)
    ↓
[2] formatting_data.py
    ↓
formatted.json (ViewValue)
    ↓
[3] html_view.py
    ↓
HTML出力
```

## 各段階の責任範囲

### [1] data_extraction.py

**責任**:
- schema.jsonベースで非computed属性を抽出
- plan.jsonから実際の値と参照情報を取得
- OriginValueオブジェクトに変換

**入力**:
- `plan.json` (dict): Terraform plan
- `schema.json` (dict): Provider schema

**出力**:
- `extracted.json`: OriginValueを含むリスト
```python
[{
  "module": str,
  "address": str,  # リソースの完全アドレス
  "type": str,     # aws_iam_role等
  "name": str,     # リソース名
  "values": dict   # OriginValueインスタンス（ネスト可）
}]
```

**OriginValue**:
```python
class OriginValue:
  value: Any          # 実際の値（参照の場合はNone）
  reference: str      # 参照先アドレス（値の場合はNone）
  required: bool      # 必須属性か
  description: str    # schema.jsonのdescription
```

### [2] formatting_data.py

**責任**:
- OriginValue → ViewValue変換
- 参照解決（`reference` → `"(ref) identifier"`）
- 特殊処理（aws_iam_role_policy_attachmentの統合等）
- 不要属性の除外（tags_all等）
- 内部情報の除去（address, module）

**入力**:
- `extracted.json`: OriginValueを含むリスト
- `options`: 除外属性リスト等

**出力**:
- `formatted.json`: ViewValueを含むリスト
```python
[{
  "resource_type": str,
  "resource_name": str,
  "values": dict  # ViewValueインスタンス（ネスト可）
}]
```

**ViewValue**:
```python
class ViewValue:
  value: Any          # 表示値（参照は "(ref) identifier"）
  description: str    # カスタムdescriptionで上書き可
  required: bool      # 必須属性か
```

**主要機能**:
1. 参照解決
   - 通常参照: `aws_iam_policy.xxx` → ポリシー名
   - モジュール参照: `module.network.vpc_id` → VPC名（tags.Name）
2. 特殊処理
   - `aws_iam_role_policy_attachment` → IAM Roleの`attached_policies`配列に統合
3. 属性除外
   - デフォルトで`tags_all`を除外

### [3] html_view.py

**責任**:
- ViewValueからHTMLテーブル生成
- リソースタイプ判定（list型 or individual型）
- ファイル配置決定（resource_config.py）
- 特殊パラメータ処理（collapsible表示等）

**入力**:
- `formatted.json`: ViewValueを含むリスト

**出力**:
- HTML文字列（複数ファイル）

**主要機能**:
1. テーブル形式決定
   - List型: `aws_iam_role`, `aws_s3_bucket`のみ
   - Individual型: その他すべて
2. ファイル配置
   - `resource_config.py`の`file_path`設定に従う
3. 特殊表示
   - JSON値: collapsible表示
   - 参照値: `→ identifier`形式
   - Tags: `Key: Value`形式（複数行）
4. 列幅制御
   - `resource_config.py`の`column_widths`設定

## 現行の問題点

### 責任範囲の曖昧さ

1. **formatting_data.pyの肥大化**
   - 参照解決
   - 特殊処理
   - 属性除外
   - ViewValue変換
   → 複数の責務が混在

2. **html_view.pyの複雑性**
   - テーブル形式判定
   - ファイル配置決定
   - HTML生成
   - 特殊パラメータ処理
   → 設定と生成が混在

3. **resource_config.pyの役割不明確**
   - ファイル配置
   - ソート順
   - 特殊パラメータ
   - 列幅
   → 設定ファイルとして独立すべき

### ブラックボックスの大きさ

- `formatting_data.py`: 420行（特殊処理の追加が困難）
- `html_view.py`: 800行以上（テーブル生成ロジックが複雑）

### 拡張性の問題

- 新しいリソースタイプの特殊処理を追加しにくい
- 参照解決ロジックの拡張が難しい
- HTML表示形式の変更が困難
